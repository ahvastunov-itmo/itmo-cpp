# Лекция 3. Структуры и объединения

> Источник: [Google Slides](https://docs.google.com/presentation/d/1T35d8A7BWSHqhICtrK9d_z1-EnlnLThijbci3W6qvro/edit)

В этой лекции рассматриваются составные типы данных в C++. Структуры позволяют объединять связанные значения в один объект, а объединения — использовать одну область памяти для нескольких альтернативных представлений.

После изучения материала вы сможете:

- объявлять и инициализировать структуры;
- создавать вложенные структуры и массивы составных объектов;
- передавать структуры в функции и работать с ними через указатели;
- объяснять, откуда в структуре появляется padding;
- управлять выравниванием осознанно;
- использовать tagged union и понимать его ограничения;
- выбирать между обычным `union` и `std::variant`.

## 1. Структуры

Структура — это пользовательский тип, объединяющий несколько связанных полей. Поля могут иметь разные типы и вместе описывать один объект предметной области.

Например, точку на плоскости удобно представить двумя координатами:

```cpp
struct Point {
    int x;
    int y;
};
```

Объявление `struct Point` создаёт новый тип. После этого можно создавать объекты этого типа:

```cpp
Point first;
Point second{200, 300};
Point third{.x = 10, .y = 20};
```

Инициализация с именами полей появилась в C++20. Поля при этом должны перечисляться в порядке их объявления.

### Доступ к полям

Для обращения к полю обычного объекта используется оператор `.`:

```cpp
#include <iostream>

struct Point {
    int x;
    int y;
};

int main() {
    Point point{};

    point.x = 200;
    point.y = 250;

    std::cout << point.x << ' ' << point.y << '\n';
}
```

Инициализация `Point point{};` обнуляет оба поля. Если написать только `Point point;`, значения полей фундаментальных типов останутся неопределёнными.

### Вложенные структуры

Полем структуры может быть объект другого пользовательского типа. Так можно собирать более сложные модели из простых компонентов:

```cpp
struct Point {
    int x;
    int y;
};

struct Rectangle {
    Point left_top;
    Point right_bottom;
};

int main() {
    Rectangle rectangle{
        .left_top = {0, 100},
        .right_bottom = {200, 0},
    };

    rectangle.left_top.x = 10;
}
```

Выражение `rectangle.left_top.x` последовательно выбирает поле `left_top`, а затем его координату `x`.

### Группировка полей

Вместо неименованных вложенных структур, которые поддерживаются не всеми компиляторами как стандартная возможность C++, лучше объявлять отдельные типы:

```cpp
struct Position {
    int x;
    int y;
};

struct Size {
    std::size_t width;
    std::size_t height;
};

struct Button {
    Position position;
    Size size;
};

Button button{
    .position = {0, 100},
    .size = {400, 80},
};
```

Такое описание явно выражает смысл каждой группы и позволяет обращаться к данным как `button.position.x` и `button.size.width`.

## 2. Операции со структурами

Для структуры компилятор обычно генерирует операции копирования и присваивания, которые обрабатывают каждое поле:

```cpp
Point first{1, 2};
Point second = first;

second.x = 10;
first = second;
```

Если все поля можно копировать, структура целиком также копируема. Можно брать её адрес, передавать в функцию и возвращать из функции.

### Структуры в функциях

Небольшую структуру удобно передать по значению и вернуть как результат:

```cpp
struct Point {
    int x;
    int y;
};

Point MakePoint(int x, int y) {
    return Point{.x = x, .y = y};
}

Point Add(Point left, Point right) {
    return Point{
        .x = left.x + right.x,
        .y = left.y + right.y,
    };
}

int main() {
    Point first = MakePoint(239, 1);
    Point second{1, 2};
    Point sum = Add(first, second);
}
```

Для крупных объектов, которые не нужно изменять, обычно используют передачу по константной ссылке:

```cpp
bool Equal(const Point& left, const Point& right) {
    return left.x == right.x && left.y == right.y;
}
```

### Массивы структур

Структуры можно хранить в массивах так же, как встроенные типы:

```cpp
#include <string>

struct Record {
    std::string name;
    std::string surname;
    long phone;
};

Record phonebook[200]{};
```

Каждый элемент массива — самостоятельный объект `Record` со своими полями.

### Указатели на структуры

Если переменная хранит указатель на структуру, для доступа к полю используется оператор `->`. Выражения `pointer->field` и `(*pointer).field` эквивалентны.

```cpp
#include <cstddef>

Record* FindRecord(long phone, Record* records, std::size_t count) {
    for (std::size_t index = 0; index < count; ++index) {
        if (records[index].phone == phone) {
            return &records[index];
        }
    }

    return nullptr;
}
```

Использование результата:

```cpp
#include <iostream>

Record* record = FindRecord(22345, phonebook, 200);

if (record != nullptr) {
    std::cout << record->name << ' ' << record->surname << '\n';
}
```

> **Важно:** указатель на элемент массива остаётся действительным только пока существует сам массив и элемент не был перемещён или удалён.

## 3. Размещение структуры в памяти

Поля структуры располагаются в памяти в порядке объявления, но между ними могут находиться неиспользуемые байты — padding. Компилятор добавляет их, чтобы каждое поле начиналось с адреса, подходящего для его типа.

Рассмотрим два типа с одинаковыми полями:

```cpp
#include <cstdint>

struct PoorLayout {
    char a;           // 1 байт
    std::int64_t b;   // 8 байт
    std::uint8_t c;   // 1 байт
    std::uint32_t d;  // 4 байта
};

struct CompactLayout {
    std::int64_t b;   // 8 байт
    std::uint32_t d;  // 4 байта
    char a;           // 1 байт
    std::uint8_t c;   // 1 байт
};
```

На распространённой 64-битной платформе `PoorLayout` часто занимает 24 байта, а `CompactLayout` — 16. Точные значения зависят от ABI, компилятора и целевой платформы.

Размер и выравнивание можно проверить программно:

```cpp
#include <cstddef>
#include <iostream>

int main() {
    std::cout << sizeof(PoorLayout) << ' ' << alignof(PoorLayout) << '\n';
    std::cout << sizeof(CompactLayout) << ' ' << alignof(CompactLayout) << '\n';

    std::cout << offsetof(PoorLayout, a) << '\n';
    std::cout << offsetof(PoorLayout, b) << '\n';
    std::cout << offsetof(PoorLayout, c) << '\n';
    std::cout << offsetof(PoorLayout, d) << '\n';
}
```

Правила в упрощённом виде:

1. адрес каждого поля должен удовлетворять требованиям его выравнивания;
2. общий размер структуры округляется до значения, кратного выравниванию структуры;
3. это позволяет корректно располагать объекты структуры подряд в массиве.

### Порядок полей

Группировка полей от большего выравнивания к меньшему часто сокращает padding. Однако менять порядок полей только ради размера стоит после измерений: логическая структура типа и совместимость формата данных могут быть важнее нескольких байтов.

### Уплотнение

Некоторые компиляторы поддерживают директивы для отключения обычного выравнивания:

```cpp
#pragma pack(push, 1)

struct PackedData {
    char a;
    std::int64_t b;
    std::uint8_t c;
    std::uint32_t d;
};

#pragma pack(pop)
```

На типичной платформе такой объект займёт 14 байт — сумму размеров полей. Но `#pragma pack` не является стандартной возможностью C++ и может ухудшить производительность. На некоторых архитектурах невыровненный доступ требует специальных инструкций или вообще недопустим.

Уплотнение обычно оправдано при работе с внешним бинарным форматом или сетевым протоколом. Даже в этом случае необходимо учитывать порядок байтов и точную спецификацию формата.

### Увеличенное выравнивание

Ключевое слово `alignas` задаёт более строгое требование к выравниванию:

```cpp
struct alignas(64) CacheAlignedData {
    char a;
    std::int64_t b;
    std::uint8_t c;
    std::uint32_t d;
};
```

Такой объект будет начинаться с адреса, кратного 64. Это применяется в низкоуровневых оптимизациях, например для размещения данных по границе кеш-линии. Использовать подобное выравнивание без измерений не следует.

## 4. Объединения

Объединение `union` похоже на структуру, но все его поля используют одну область памяти. В каждый момент времени активным считается только один член объединения.

```cpp
#include <cstdint>

union Value {
    std::int64_t integer;
    double real;
    char text[16];
};
```

Размер `Value` достаточен для самого крупного поля с учётом выравнивания. Запись нового поля переключает активный член:

```cpp
Value value{};

value.integer = 239;
// Здесь активен value.integer.

value.real = 3.14;
// Теперь активен value.real.
```

> **Важно:** чтение неактивного поля обычного `union` в общем случае приводит к неопределённому поведению в C++. Поэтому union нельзя использовать как переносимый способ произвольного переосмысления битов одного типа как другого.

Для безопасного копирования битового представления применяют `std::memcpy`, а для типов одинакового размера в C++20 доступен `std::bit_cast`.

### Tagged union

Само объединение не хранит информацию о том, какое поле активно. Эту информацию можно добавить отдельно в виде тега:

```cpp
struct Point {
    float x;
    float y;
};

struct Triangle {
    Point a;
    Point b;
    Point c;
};

struct Rectangle {
    Point left_top;
    Point right_bottom;
};

struct Circle {
    Point center;
    float radius;
};

enum class FigureType {
    Triangle,
    Rectangle,
    Circle,
};

union FigureData {
    Triangle triangle;
    Rectangle rectangle;
    Circle circle;
};

struct Figure {
    FigureType type;
    FigureData data;
};
```

Код, работающий с `Figure`, обязан проверять `type` и обращаться только к соответствующему полю `data`. Ошибка в теге приводит к чтению неактивного члена.

Преимущество такого представления — память выделяется только под самый большой вариант, а не под все фигуры одновременно. Цена — ручное управление активным полем и временем жизни сложных объектов.

### `std::variant`

В современном C++ безопасной альтернативой tagged union является `std::variant`:

```cpp
#include <variant>

using Figure = std::variant<Triangle, Rectangle, Circle>;

Figure figure = Circle{
    .center = {0.0F, 0.0F},
    .radius = 10.0F,
};
```

`std::variant` самостоятельно хранит тег и контролирует время жизни активного объекта. Для обработки вариантов используются `std::get`, `std::get_if` и `std::visit`.

## 5. Измерение производительности

Предположение об оптимизации нужно подтверждать измерением. Для небольших фрагментов кода удобно использовать Google Benchmark или онлайн-сервис [Quick Bench](https://quick-bench.com/).

Минимальная форма теста Google Benchmark:

```cpp
#include <benchmark/benchmark.h>

static void PointAddition(benchmark::State& state) {
    Point first{1, 2};
    Point second{3, 4};

    for (auto _ : state) {
        Point result = Add(first, second);
        benchmark::DoNotOptimize(result);
    }
}

BENCHMARK(PointAddition);
BENCHMARK_MAIN();
```

`benchmark::DoNotOptimize` не позволяет компилятору удалить вычисление как неиспользуемое. Библиотека самостоятельно выполняет прогрев, многократные запуски и статистическую обработку времени.

![Пример сравнения результатов в Quick Bench](assets/03-struct-union/slide-27-image-01.png)

На графике меньшее значение означает более быстрое выполнение. Однако красивый результат не делает небезопасный код корректным: нельзя оправдывать выигрышем по времени чтение неактивного поля `union` или другое неопределённое поведение.

При сравнении вариантов важно:

- использовать одинаковые входные данные;
- не позволять компилятору удалить измеряемую работу;
- запускать оптимизированную сборку;
- проверять корректность обоих вариантов;
- повторять измерения на целевых платформах;
- оценивать не только скорость, но и читаемость и переносимость.

## Итоги

- Структура объединяет связанные поля в один пользовательский тип.
- Поля структуры располагаются в порядке объявления, но между ними может быть padding.
- Порядок полей влияет на размер объекта, хотя конкретная раскладка зависит от платформы.
- `#pragma pack` уменьшает padding ценой переносимости и возможной потери производительности.
- Все поля `union` используют одну область памяти, но активным является только одно.
- Для альтернативных типов в современном C++ обычно безопаснее `std::variant`.
- Любую оптимизацию необходимо подтверждать корректным бенчмарком.
