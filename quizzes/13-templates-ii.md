## Полная специализация

Что задаёт полная специализация шаблона класса?

::: {.quiz-options}
1. Общую реализацию для всех указателей без фиксации типа.
2. Новое правило приоритета операторов.
3. Параметры, выбираемые только при запуске.
4. Отдельную реализацию для конкретного набора аргументов шаблона.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Отдельную реализацию для фиксированных аргументов.** Например, специализация для `Box<bool>` отличается от общего шаблона `Box<T>`.

[Повторить: Full template specialization](../lectures/13-templates-ii.md#full-template-specialization){target="_blank"}

</details>

## Пустой список параметров

Какой префикс обычно вводит явную полную специализацию?

::: {.quiz-options}
1. `override`.
2. `template<class...>`.
3. `virtual template`.
4. `template<>`.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**`template<>`.** Все аргументы уже указаны в специализации, новых параметров шаблона у неё не остаётся.

[Повторить: Full template specialization](../lectures/13-templates-ii.md#full-template-specialization){target="_blank"}

</details>

## Частичная специализация

Чем частичная специализация класса отличается от полной?

::: {.quiz-options}
1. Сохраняет параметры и описывает семейство подходящих аргументов.
2. Не может содержать методов.
3. Работает только с `int`.
4. Всегда выполняется медленнее.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Часть параметризации сохраняется.** Например, вариант для `Box<T*>` подходит для указателей на разные `T`.

[Повторить: Частичная специализация](../lectures/13-templates-ii.md#частичная-специализация){target="_blank"}

</details>

## Специализация для указателей

У шаблона `Box<T>` есть частичная специализация `Box<T*>`. Какой вариант подходит к `Box<int*>`?

::: {.quiz-options}
1. Ни один: указатели не могут быть аргументами.
2. Специализация для указателей с `T = int`.
3. Полная специализация для `double`.
4. Только первичный шаблон.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Подходит `Box<T*>` с `T = int`.** Частичная специализация выбирается по структуре аргумента шаблона.

[Повторить: Частичная специализация](../lectures/13-templates-ii.md#частичная-специализация){target="_blank"}

</details>

## Шаблоны функций

Что используют вместо частичной специализации шаблона функции, которая языком не разрешена?

::: {.quiz-options}
1. Изменение возвращаемого типа при запуске.
2. Перегрузку функции или шаблона функции.
3. Только макрос без типов.
4. Только виртуальное наследование.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Используют перегрузки.** Полная явная специализация функции возможна, но частичные специализации предусмотрены для других шаблонных сущностей, в том числе классов.

[Повторить: Специализация шаблонов функций](../lectures/13-templates-ii.md#специализация-шаблонов-функций){target="_blank"}

</details>

## Собственный интерфейс

Обязана ли явно полностью специализированная версия класса повторять все члены первичного шаблона?

::: {.quiz-options}
1. Только если в имени есть `bool`.
2. Да, иначе будет ошибка компоновки.
3. Да, побайтово.
4. Нет: специализация определяет собственные члены.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Члены могут отличаться.** Полная специализация — отдельное определение; используемый обобщённый код всё равно должен находить ожидаемый интерфейс у выбранного типа.

[Повторить: Специализация шаблона класса](../lectures/13-templates-ii.md#специализация-шаблона-класса){target="_blank"}

</details>

## RAII при исключении

Почему локальная RAII-обёртка помогает при раскрутке стека?

::: {.quiz-options}
1. Исключения автоматически запрещаются.
2. Обёртка перехватывает любое исключение без кода.
3. Все ресурсы становятся глобальными.
4. Для полностью созданной обёртки вызывается деструктор, освобождающий ресурс.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Срабатывает деструктор локального владельца.** Освобождение связано со временем жизни объекта и не требует ручного `delete` на каждой ветви.

[Повторить: RAII](../lectures/13-templates-ii.md#raii){target="_blank"}

</details>

## Исторический auto_ptr

Почему `auto_ptr` в лекции рассматривается как исторический пример?

::: {.quiz-options}
1. Он нужен для любого современного массива.
2. Он является другим именем `shared_ptr`.
3. Он устарел в C++11 и удалён из стандарта в C++17.
4. Его добавили только в C++20.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**В C++20 стандартного `auto_ptr` уже нет.** Передача владения при копировании была неожиданной; современный `unique_ptr` явно выражает перемещение.

[Повторить: auto_ptr](../lectures/13-templates-ii.md#auto_ptr){target="_blank"}

</details>

## Выбор владения

Один объект должен иметь одного владельца с возможностью передать владение. Какой стандартный указатель подходит?

::: {.quiz-options}
1. `std::weak_ptr`.
2. `std::unique_ptr`.
3. Только `std::shared_ptr`.
4. Обычный `void*` как автоматический владелец.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**`std::unique_ptr`.** Он запрещает копирование и допускает передачу владения через перемещение.

[Повторить: unique_ptr](../lectures/13-templates-ii.md#unique_ptr){target="_blank"}

</details>

## Наблюдение без владения

Какой указатель позволяет наблюдать за объектом под управлением `shared_ptr`, не увеличивая число сильных владельцев?

::: {.quiz-options}
1. `std::unique_ptr` на тот же сырой адрес.
2. `std::weak_ptr`.
3. `std::auto_ptr` в C++20.
4. Второй `std::shared_ptr`.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**`std::weak_ptr`.** Через `lock()` можно попытаться получить временное сильное владение, если объект ещё существует.

[Повторить: std::weak_ptr](../lectures/13-templates-ii.md#stdweak_ptr){target="_blank"}

</details>
