## Инвариант

Что называют инвариантом класса?

::: {.quiz-options}
1. Список подключённых заголовков.
2. Адрес первого поля.
3. Любой публичный метод.
4. Условие корректности его состояния.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Инвариант описывает корректное состояние.** Конструктор устанавливает его, а операции класса должны сохранять согласованность объекта.

</details>

## Граница интерфейса

Зачем скрывать внутренние поля за методами класса?

::: {.quiz-options}
1. Чтобы запретить любое использование объекта.
2. Чтобы компилятор всегда создавал поток.
3. Чтобы контролировать изменения и поддерживать инвариант.
4. Чтобы тип перестал занимать память.

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Методы контролируют допустимые изменения.** Инкапсуляция позволяет менять представление объекта, сохраняя понятный внешний интерфейс.

## class и struct

Чем различаются `class` и `struct` по доступу к членам по умолчанию?

::: {.quiz-options}
1. У `struct` не бывает методов.
2. У `class` — `private`, у `struct` — `public`.
3. У `class` — `public`, у `struct` — `private`.
4. Оба всегда `private`.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**`class` по умолчанию закрывает члены, `struct` открывает.** Оба могут иметь методы, конструкторы и модификаторы доступа.

[Повторить: class/struct](../lectures/08-oop-abstraction-encapsulation.md#classstruct){target="_blank"}

</details>

Какова основная задача конструктора?

## Порядок полей

В каком порядке инициализируются нестатические поля объекта?

## const-метод

Что означает `const` после списка параметров нестатического метода?

::: {.quiz-options}
1. Метод обязан возвращать `const int`.
2. Через `this` нельзя менять нестатические поля без `mutable`.
3. Метод не может быть вызван у неконстантного объекта.
4. Все аргументы копируются как `const`.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Метод получает доступ через указатель на константный объект.** Обычные поля защищены от изменения; для полей `mutable` предусмотрено исключение.

[Повторить: !NB. const method](../lectures/08-oop-abstraction-encapsulation.md#nb.-const-method){target="_blank"}

</details>

## Деструктор

За что отвечает деструктор класса, владеющего ресурсом?

::: {.quiz-options}
1. За поиск всех указателей на объект в программе.
2. За повторный вызов конструктора.
3. За освобождение принадлежащего объекту ресурса при завершении его жизни.
4. Только за удаление имени переменной.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**За завершение владения ресурсом.** Деструктор — основа RAII; он не ищет и не исправляет внешние висячие указатели.

[Повторить: Destructor](../lectures/08-oop-abstraction-encapsulation.md#destructor){target="_blank"}

</details>

## Запрет операции

Как явно запретить копирующий конструктор класса?

::: {.quiz-options}
1. Добавить `const` к возвращаемому типу.
2. Написать `= default`.
3. Объявить его с `= delete`.
4. Сделать имя длиннее.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**`= delete` запрещает использование функции.** `= default`, напротив, запрашивает реализацию специальной функции у компилятора.

[Повторить: default, delete](../lectures/08-oop-abstraction-encapsulation.md#default-delete){target="_blank"}

</details>

## Неявные преобразования

Для чего помечают подходящий конструктор словом `explicit`?

::: {.quiz-options}
1. Чтобы ограничить неявные преобразования через него.
2. Чтобы удалить деструктор.
3. Чтобы обязательно выделять объект в куче.
4. Чтобы сделать класс абстрактным.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**`explicit` ограничивает неявное создание объекта через конструктор.** При этом подходящая явная прямая инициализация остаётся возможной.

[Повторить: Неявное преобразование типов](../lectures/08-oop-abstraction-encapsulation.md#неявное-преобразование-типов){target="_blank"}

</details>

## Правило трёх

Какие функции входят в правило трёх? Выберите все верные варианты.

::: {.quiz-options}
1. Деструктор.
2. Копирующий конструктор.
3. Копирующее присваивание.
4. Любой конструктор с тремя параметрами.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Деструктор, копирующий конструктор и копирующее присваивание.** Если класс вручную управляет ресурсом, их поведение нужно согласовать, чтобы избежать утечек и двойного освобождения.

[Повторить: Rule of three](../lectures/08-oop-abstraction-encapsulation.md#rule-of-three){target="_blank"}

</details>
