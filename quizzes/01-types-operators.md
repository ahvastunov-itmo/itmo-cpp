## Идентификаторы

Какие имена подходят для локальной переменной в C++? Выберите все верные варианты.

::: {.quiz-options}
1. `student_count`
2. `2students`
3. `double`
4. `Value`
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

Верны **`student_count` и `Value`**. Имя не может начинаться с цифры, а `double` — ключевое слово. Прописные буквы допустимы: `value` и `Value` — разные имена. Правила языка и соглашения о стиле именования — разные вещи.

## Размеры типов

Какое утверждение гарантирует стандарт C++ на любой поддерживаемой платформе?

::: {.quiz-options}
1. `sizeof(int) == 4`.
2. `sizeof(long) == 8`.
3. `sizeof(char) == 1`.
4. В одном байте всегда ровно восемь бит.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

Гарантировано **`sizeof(char) == 1`**. Размеры `int` и `long` зависят от платформы. `sizeof` измеряет размер в байтах C++, а количество бит в таком байте задаёт `CHAR_BIT`: оно не обязано быть равно восьми.

[Повторить: размеры типов](../lectures/01-types-operators.md#размеры-типов-зависят-от-платформы){target="_blank"}

## Целочисленные литералы

Что программа выведет **в первой строке**?

```{.cpp filename="integer-literals.cpp"}
{{< include ../examples/01-types-operators/integer-literals.cpp >}}
```

::: {.quiz-options}
1. `162 242 162 162`
2. `162 162 162 162`
3. `162 0242 0xA2 0b1010'0010`
4. Программа не скомпилируется из-за апострофа в числе.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

Первая строка — **`162 162 162 162`**. Все четыре литерала обозначают одно число. Ведущий ноль задаёт восьмеричную запись: `0242` = 2 × 64 + 4 × 8 + 2 = 162. Префиксы `0x` и `0b` задают другие системы счисления, а апостроф лишь разделяет разряды. По умолчанию поток печатает целые числа в десятичной системе.

## Преобразования типов

Какую строку выведет программа?

```{.cpp filename="type-conversions.cpp"}
{{< include ../examples/01-types-operators/type-conversions.cpp >}}
```

::: {.quiz-options}
1. `3 4`
2. `3 3`
3. `3 3.75`
4. Программа не скомпилируется: преобразовать `double` в `int` нельзя.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

Программа выведет **`3 3`**. Число 3 точно представимо как `double`; поток с настройками по умолчанию печатает его как `3`. Преобразование `(int)3.75` отбрасывает дробную часть, а не округляет до ближайшего целого. Здесь результат помещается в `int`.

## Беззнаковая арифметика

Чему равно выражение `0U - 1U`? Конкретную ширину `unsigned int` не предполагаем.

::: {.quiz-options}
1. Целому числу `-1` типа `int`.
2. Нулю: беззнаковое значение не может стать отрицательным.
3. Максимальному значению типа `unsigned int`.
4. Выражение всегда вызывает неопределённое поведение.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

Результат — **максимум `unsigned int`**. Беззнаковая арифметика выполняется по модулю 2ᴺ, где N — число значащих битов типа. Поэтому вычитание единицы из нуля даёт 2ᴺ − 1. Это определённое поведение; правила переполнения знаковых типов другие.

[Повторить: арифметика unsigned](../lectures/01-types-operators.md#арифметика-unsignedcppref-types-standard-integer-types){target="_blank"}

</details>

## Дополнительный код

Как выглядит число **−5** в восьмибитном дополнительном коде?

::: {.quiz-options}
1. `0000 0101`
2. `1000 0101`
3. `1111 1010`
4. `1111 1011`
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

Правильный шаблон — **`1111 1011`**. Для +5 получаем `0000 0101`, инвертируем биты: `1111 1010`, затем прибавляем единицу. Шаблон `1000 0101` соответствовал бы −5 в прямом коде, а `1111 1010` — в обратном.

## Вещественные литералы

Какие литералы имеют тип **`float`**? Выберите все верные варианты.

::: {.quiz-options}
1. `1.0F`
2. `1e3`
3. `2.5L`
4. `0.5f`
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

Тип `float` имеют **`1.0F` и `0.5f`**: суффиксы `F` и `f` равнозначны. Литерал `1e3` имеет тип `double`, хотя его значение — целое число 1000. Суффикс `L` у вещественного литерала задаёт `long double`.

## Перечисления

Что верно для `enum class Direction { kLeft, kRight };`, объявленного на уровне пространства имён?

::: {.quiz-options}
1. Вне перечисления элемент доступен просто как `kLeft`.
2. К элементу можно обратиться как `Direction::kLeft`; неявного преобразования в `int` нет.
3. Элемент `Direction::kLeft` неявно преобразуется в `int`, как элемент обычного `enum`.
4. `enum class` используется только для строковых значений.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

Верно **второе утверждение**. Элементы `enum class` находятся в области видимости перечисления. Например, `int value = Direction::kLeft;` не скомпилируется: для получения целого значения нужно явное преобразование.

[Повторить: enum и enum class](../lectures/01-types-operators.md#enumcppref-enum-enum-classcppref-enum){target="_blank"}

</details>

## Чтение без инициализации

Значение локальной переменной `value` перед чтением не задано. Как это влияет на программу в **C++20**? Это пример ошибки для анализа; запускать его не нужно.

```{.cpp filename="uninitialized-local.cpp"}
{{< include ../examples/01-types-operators/uninitialized-local.cpp >}}
```

::: {.quiz-options}
1. Программа обязана вывести ноль.
2. Программа всегда выводит произвольное число, но в остальном работает корректно.
3. Компилятор обязан отклонить программу.
4. Чтение вызывает неопределённое поведение; стандарт не гарантирует конкретный результат.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

Верно **четвёртое утверждение**. Чтение неопределённого значения локального `int` в этом примере — undefined behavior в C++20. Это не обещание «случайного числа»: стандарт не ограничивает последствия. Исправление — задать значение до чтения, например `int value = 0;`.

## Порядок вычислений и деление

Каковы значение и тип выражения `7 / 2 + 1.0`?

::: {.quiz-options}
1. Значение 4, тип `double`.
2. Значение 4.5, тип `double`.
3. Значение 4, тип `int`.
4. Значение 3, тип `int`.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

Результат — **4 типа `double`**. Сначала выполняется целочисленное деление `7 / 2`, которое даёт 3. Затем для сложения с `1.0` значение 3 преобразуется в `double`. Вещественный операнд в сложении не меняет уже выполненное целочисленное деление.
