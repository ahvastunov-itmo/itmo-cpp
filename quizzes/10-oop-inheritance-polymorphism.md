## Отношение is-a

Когда публичное наследование лучше отражает модель предметной области?

::: {.quiz-options}
1. Когда производный объект допустимо использовать как объект базового типа.
2. Когда просто нужны два одинаковых поля.
3. Когда типы вообще не связаны по смыслу.
4. Когда требуется запретить базовый интерфейс.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Публичное наследование выражает is-a.** Производный тип должен сохранять смысл обещаний базового интерфейса; повторное использование кода само по себе недостаточно.

</details>

## Базовый подобъект

Что содержит обычный объект производного класса?

::: {.quiz-options}
1. Базовый подобъект и собственные подобъекты.
2. Только указатель на отдельно созданного родителя.
3. Обязательно копию каждого объекта базового класса в программе.
4. Только свои новые поля, базовых данных нет.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**В объект входит базовый подобъект.** Он конструируется как часть производного объекта, а не как произвольный внешний объект.

</details>

## Порядок конструирования

Для простого одиночного наследования в каком порядке выполняются тела конструкторов?

::: {.quiz-options}
1. Сначала производного, затем базового.
2. Порядок случаен.
3. Сначала базового класса, затем производного.
4. Всегда одновременно.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Сначала база, затем производный класс.** Производная часть начинает работу после инициализации базовой.

## Срезка объекта

Что происходит при копировании производного объекта в отдельный объект базового типа по значению?

::: {.quiz-options}
1. Производный объект уничтожается.
2. Новый объект автоматически становится указателем.
3. Сохраняется весь динамический тип.
4. Копируется только базовая часть: происходит slicing.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Происходит срезка.** Базовый объект по значению не хранит добавленную производную часть; для полиморфизма обычно используют ссылки или указатели.

[Повторить: Наследование](../lectures/10-oop-inheritance-polymorphism.md#наследование){target="_blank"}

</details>

## Множественное наследование

Может ли класс C++ непосредственно наследоваться от двух разных классов?

::: {.quiz-options}
1. Только если оба не содержат методов.
2. Да.
3. Нет, только от одного.
4. Только с `std::variant`.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Да, язык поддерживает множественное наследование.** При проектировании нужно учитывать неоднозначности имён и структуру базовых подобъектов.

## Ромб

Класс наследуется от двух классов, у которых есть общая невиртуальная база. Сколько подобъектов этой общей базы обычно входит в такой ромб?

::: {.quiz-options}
1. Бесконечно много.
2. Два, по одному через каждую ветвь.
3. Ни одного.
4. Всегда один.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Два базовых подобъекта.** Виртуальное наследование позволяет разделять один общий подобъект базы, но меняет устройство и правила инициализации.

[Повторить: Diamond Problem](../lectures/10-oop-inheritance-polymorphism.md#diamond-problem){target="_blank"}

</details>

## Виртуальный вызов

Базовая ссылка обозначает производный объект, переопределивший виртуальный метод. Какой метод выбирается обычным виртуальным вызовом?

::: {.quiz-options}
1. Только самый короткий по коду.
2. Случайный метод.
3. Всегда базовый.
4. Переопределение для динамического типа объекта.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Выбор учитывает динамический тип.** Это основа динамического полиморфизма; копирование в базовый объект по значению изменило бы ситуацию.

</details>

## Абстрактный класс

Можно ли непосредственно создать объект класса, у которого остаётся чисто виртуальная функция?

::: {.quiz-options}
1. Да, только в куче.
2. Нет, такой класс абстрактный.
3. Да, если не вызывать эту функцию.
4. Да, но лишь один объект.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Нельзя создать объект абстрактного класса.** При этом указатели и ссылки на него допустимы и используются для общего интерфейса.

[Повторить: Абстрактный класс](../lectures/10-oop-inheritance-polymorphism.md#абстрактный-класс){target="_blank"}

</details>
