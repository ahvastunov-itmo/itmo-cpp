## Этапы сборки

Какой порядок соответствует обычной сборке программы из исходников?

::: {.quiz-options}
1. Только компоновка, остальные этапы не нужны.
2. Запуск, компиляция, препроцессор.
3. Компоновка, препроцессор, компиляция.
4. Препроцессор, компиляция, компоновка.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Препроцессор → компиляция → компоновка.** Сначала обрабатываются директивы, затем формируется объектный код, после чего связываются определения.

</details>

## Объявление функции

Что сообщает объявление `int sum(int, int);` без тела?

::: {.quiz-options}
1. Адрес всех вызовов функции.
2. Имя, тип результата и типы параметров.
3. Как именно вычисляется сумма.
4. Что функция уже вызвана.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Объявление задаёт интерфейс функции.** Тело с реализацией находится в определении.

## Заголовочный файл

Зачем выносить общий интерфейс в заголовок?

::: {.quiz-options}
1. Чтобы заголовок запускался как отдельная программа.
2. Чтобы несколько единиц трансляции использовали согласованные объявления.
3. Чтобы автоматически скрыть все определения от линкера.
4. Чтобы каждый вызов компилировался без объявления.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Заголовок даёт общие объявления.** Его подключают там, где нужен интерфейс, а изменение объявления выполняют в одном месте.

## Стражи включения

От какой проблемы защищают include guards?

::: {.quiz-options}
1. От гонок потоков.
2. От повторной обработки содержимого заголовка в одной единице трансляции.
3. От любого нарушения ODR во всей программе.
4. От ошибок типов в функции.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**От повторного включения в одной единице трансляции.** Они не разрешают размещать произвольные не-`inline` определения в заголовке, включённом в разные `.cpp`.

[Повторить: Стражи](../lectures/07-compiler-preprocessor.md#стражи){target="_blank"}

</details>

## Макрос и скобки

Макрос определён как `#define DOUBLE(x) x + x`. Во что он разворачивает `DOUBLE(3) * 2`?

::: {.quiz-options}
1. `(3 + 3) * 2`, что даёт `12`.
2. `3 + 3 * 2`, что даёт `9`.
3. В вызов обычной функции.
4. `3 * 2`, что даёт `6`.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Получается `3 + 3 * 2`.** Макрос подставляет токены; приоритет умножения сохраняется. Скобки вокруг выражения нужны для предсказуемой группировки.

[Повторить: Макросы](../lectures/07-compiler-preprocessor.md#макросы){target="_blank"}

</details>

## Повторное вычисление

Макрос использует свой аргумент дважды. Почему передавать в него выражение с побочным эффектом рискованно?

::: {.quiz-options}
1. Препроцессор проверит время жизни всех объектов.
2. Макрос гарантированно вычислит его ровно один раз.
3. После подстановки выражение может вычисляться несколько раз.
4. Все побочные эффекты будут удалены.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Аргумент может оказаться в результирующем коде несколько раз.** Скобки решают проблему группировки, но не проблему повторного вычисления.

[Повторить: Макросы](../lectures/07-compiler-preprocessor.md#макросы){target="_blank"}

</details>

## Ошибка компоновки

Функция объявлена и вызывается, но требуемое определение не попало в сборку. На каком этапе обычно появится `undefined reference`/`undefined symbol`?

::: {.quiz-options}
1. При обработке комментариев.
2. При компоновке.
3. При форматировании.
4. Только при вводе данных пользователем.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**При компоновке.** Компилятору могло хватить объявления, а линкеру нужно связать вызов с определением.

[Повторить: Компоновщик(линкер)](../lectures/07-compiler-preprocessor.md#компоновщиклинкер){target="_blank"}

</details>

## Локальный static

Какова продолжительность хранения обычной локальной переменной со спецификатором `static`?

::: {.quiz-options}
1. Статическая: её значение сохраняется между вызовами.
2. Только один машинный такт.
3. Всегда динамическая, до `delete`.
4. Только до конца текущей инструкции.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Статическая продолжительность хранения.** Область видимости имени остаётся локальной; это отдельное свойство от продолжительности хранения.

[Повторить: Storage duration](../lectures/07-compiler-preprocessor.md#storage-duration){target="_blank"}

</details>

## Внутреннее связывание

Что даёт `static` обычной функции на уровне пространства имён?

::: {.quiz-options}
1. Запрет на вызовы из того же файла.
2. Внутреннее связывание имени в пределах единицы трансляции.
3. Автоматическое создание потока.
4. Динамическую диспетчеризацию.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Внутреннее связывание.** Такое имя не обозначает общую функцию для других единиц трансляции; это не то же самое, что локальный `static`-объект.

[Повторить: Storage duration and linkage](../lectures/07-compiler-preprocessor.md#storage-duration-and-linkage){target="_blank"}

</details>
