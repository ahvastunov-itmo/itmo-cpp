## Статический тип и вызов

`Base&` связан с `Derived`, но вызываемый метод базы невиртуальный. От чего зависит выбор метода при обычном вызове через эту ссылку?

::: {.quiz-options}
1. От случайного адреса.
2. От размера объекта.
3. Только от динамического типа.
4. От статического типа выражения.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**От статического типа `Base&`.** Динамический выбор реализации требует виртуальной функции.

## Проверка override

В производном классе написан метод с `override`, но его сигнатура не переопределяет ни одну виртуальную функцию базы. Что будет?

::: {.quiz-options}
1. Случайный выбор функции при запуске.
2. Молчаливое создание несвязанной перегрузки.
3. Автоматическое исправление сигнатуры.
4. Ошибка компиляции.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Компилятор сообщит об ошибке.** `override` помогает заметить расхождение параметров или квалификаторов с базовым методом.

[Повторить: override](../lectures/11-oop-polymorphism.md#override){target="_blank"}

</details>

## final для метода

Что запрещает `final` у виртуального метода?

::: {.quiz-options}
1. Создание объекта содержащего его класса.
2. Дальнейшее переопределение в потомках.
3. Его наличие в базовом классе.
4. Его вызов через базовую ссылку.

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Дальнейшее переопределение.** Сам класс при этом может оставаться открытым для наследования, если не помечен `final`.

## Удаление через базу

Объект `Derived` создан через `new`, удаляется через `Base*` обычным `delete`, а деструктор базы невиртуальный. Как оценить такой код?

::: {.quiz-options}
1. Он всегда вызывает оба деструктора правильно.
2. Он гарантированно не компилируется.
3. Он только теряет имя переменной.
4. Это неопределённое поведение.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Это неопределённое поведение.** Для обычного полиморфного удаления через базовый указатель нужен виртуальный деструктор. Здесь анализируется ошибка, а не пример для запуска.

[Повторить: Virtual destructor](../lectures/11-oop-polymorphism.md#virtual-destructor){target="_blank"}

</details>

## Полиморфная коллекция

База конкретная. Как хранить разные производные объекты без срезки, с единоличным владением?

::: {.quiz-options}
1. В `std::vector<Base>` копированием по значению.
2. В `std::vector<std::unique_ptr<Base>>` с подходящим виртуальным деструктором базы.
3. В `std::vector<void>` без информации о типе.
4. Только в массиве `int`.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Контейнер владеющих указателей сохраняет производные объекты.** Контейнер базовых значений при копировании производного объекта срежет производную часть.

[Повторить: Коллекции полиморфных объектов](../lectures/11-oop-polymorphism.md#коллекции-полиморфных-объектов){target="_blank"}

</details>

## Таблица виртуальных функций

Какое утверждение о vtable корректно?

::: {.quiz-options}
1. В таблице хранятся все локальные переменные.
2. Стандарт требует одинакового бинарного формата vtable у всех компиляторов.
3. Это распространённый механизм реализации, но стандарт не требует именно такой структуры.
4. Таблица обязательно выделяется отдельно на каждый вызов.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Vtable — обычный способ реализации виртуальных вызовов.** Стандарт описывает поведение языка, а конкретный механизм и ABI зависят от реализации.

[Повторить: Таблица виртуальных функций](../lectures/11-oop-polymorphism.md#таблица-виртуальных-функций){target="_blank"}

</details>

## Non-Virtual Interface

Как обычно устроена идиома NVI?

::: {.quiz-options}
1. Виртуальные функции полностью запрещаются.
2. Публичный невиртуальный метод задаёт общий порядок действий и вызывает виртуальный шаг.
3. Все поля становятся публичными.
4. Пользователь напрямую меняет vtable.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Общий алгоритм остаётся в невиртуальном интерфейсе.** Производные классы меняют отдельные шаги, а базовый код сохраняет общие проверки и порядок.

[Повторить: Non-Virtual Interface Idiom](../lectures/11-oop-polymorphism.md#non-virtual-interface-idiom){target="_blank"}

</details>

## Виртуальный друг

Как свободная функция вывода может поддержать динамический полиморфизм?

::: {.quiz-options}
1. Всегда копировать объект в базовый тип.
2. Сравнить размеры типов.
3. Стать свободной `virtual`-функцией.
4. Делегировать работу виртуальному методу объекта.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Делегировать виртуальному методу.** Свободные функции не бывают виртуальными, но могут запускать виртуальный вызов через объект.

[Повторить: Virtual Friend Function Idiom](../lectures/11-oop-polymorphism.md#virtual-friend-function-idiom){target="_blank"}

</details>

## Цена полиморфизма

Какие последствия виртуального вызова возможны? Выберите все верные варианты.

::: {.quiz-options}
1. Косвенный вызов через адрес функции.
2. Более сложное встраивание функции оптимизатором.
3. Гарантированное ускорение любого алгоритма.
4. Одинаковая цена на всех платформах.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Возможны косвенный вызов и затруднение инлайнинга.** Это не фиксированный штраф: оптимизатор иногда устраняет виртуальность конкретного вызова.

[Повторить: Стоимость виртуальных функций](../lectures/11-oop-polymorphism.md#стоимость-виртуальных-функций){target="_blank"}

</details>

## Интерфейс абстрактной базы

Какие действия допустимы с абстрактным базовым классом? Выберите все верные варианты.

::: {.quiz-options}
1. Создать его самостоятельный объект.
2. Связать ссылку на базу с подходящим конкретным потомком.
3. Передать такой объект через указатель на базу.
4. Предположить, что в базе не может быть реализованных методов.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Ссылки и указатели допустимы.** Абстрактная база задаёт интерфейс и может содержать реализацию некоторых методов; непосредственно создать её объект нельзя.

[Повторить: Абстрактный класс](../lectures/11-oop-polymorphism.md#абстрактный-класс){target="_blank"}

</details>
