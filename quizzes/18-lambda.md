## Тип замыкания

Что создаётся при вычислении лямбда-выражения?

::: {.quiz-options}
1. Новый поток.
2. Объект уникального безымянного типа замыкания.
3. Всегда только сырой указатель на функцию.
4. Всегда экземпляр `std::function`.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Создаётся объект замыкания.** У его типа есть оператор вызова; захваченные по значению данные хранятся в объекте.

[Повторить: Lambda (C++11)](../lectures/18-lambda.md#lambda-c11){target="_blank"}

</details>

## Захват по значению

`int x = 1;` захвачен в лямбде `[x]`, которая возвращает `x`. До вызова лямбды внешнему `x` присвоили `9`. Что она вернёт?

::: {.quiz-options}
1. `1`.
2. Значение не определено во всех случаях.
3. Адрес `x`.
4. `9`.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Вернётся сохранённая копия `1`.** Изменение внешнего `int` после создания замыкания не меняет эту копию.

[Повторить: Capture](../lectures/18-lambda.md#capture){target="_blank"}

</details>

## Захват по ссылке

Лямбда захватывает локальный `int x` через `[&x]` и возвращает `x`. До вызова внешнему `x` присвоили `9`; объект ещё жив. Что вернётся?

::: {.quiz-options}
1. Всегда `0`.
2. Копия адреса как число.
3. `9`.
4. Всегда `1`.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Вернётся текущее значение `9`.** Лямбда обращается к исходному объекту, поэтому важны его время жизни и синхронизация доступа.

[Повторить: Capture](../lectures/18-lambda.md#capture){target="_blank"}

</details>

## mutable

Что позволяет `mutable` у лямбды с захваченным по значению обычным `int`?

::: {.quiz-options}
1. Продлить жизнь всех ссылочных захватов.
2. Сделать все обращения атомарными.
3. Изменять только исходный внешний `int`.
4. Изменять внутреннюю копию захваченного значения.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Можно изменять копию в замыкании.** Это не превращает захват по значению в захват по ссылке.

## Два одинаковых текста

Два отдельных лямбда-выражения имеют одинаковый текст `[] { return 1; }`. Совпадают ли их типы?

::: {.quiz-options}
1. Совпадают только в одном файле.
2. У лямбд вообще нет типа.
3. Всегда совпадают.
4. Нет, у отдельных лямбда-выражений разные типы замыканий.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Типы различаются.** Совпадение тела и сигнатуры вызова не делает два отдельных выражения одним типом.

## Указатель на функцию

Какая обычная необобщённая лямбда может преобразоваться в совместимый указатель на функцию в C++20?

::: {.quiz-options}
1. Только лямбда с `[this]`.
2. Лямбда с пустым списком захвата `[]`.
3. Любая лямбда, включая захват по ссылке.
4. Только лямбда с копией `std::string`.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Лямбда без захватов.** Указателю на функцию негде хранить индивидуальное состояние замыкания с захваченными значениями.

[Повторить: Function Pointer & Lambda](../lectures/18-lambda.md#function-pointer-lambda){target="_blank"}

</details>

## Обобщённая лямбда

Что означает параметр `auto value` у лямбды в C++20?

::: {.quiz-options}

2. Захват всех внешних переменных.

## Опасное время жизни

Функция возвращает лямбду, захватившую обычную локальную переменную по ссылке. После возврата лямбда читает эту переменную. Что не так?

::: {.quiz-options}
1. Лямбда автоматически копирует переменную при возврате.
2. Ссылка стала висячей, чтение даёт неопределённое поведение.
3. Ничего: захват по ссылке всегда продлевает жизнь.
4. Возврат лямбд запрещён.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Захват по ссылке не продлевает время жизни объекта.** Это анализ ошибки; для независимого значения подходит захват по значению.

[Повторить: Capture](../lectures/18-lambda.md#capture){target="_blank"}

</details>

## std::function

Для чего используют `std::function<int(int)>`?

::: {.quiz-options}
1. Только для хранения одного конкретного типа лямбды.
2. Для хранения подходящих копируемых вызываемых объектов за общим интерфейсом.
3. Для автоматического распараллеливания вызовов.
4. Только для сырой памяти.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Это полиморфная обёртка вызываемых объектов.** В C++20 её цель должна удовлетворять требованию копируемости; совместимой сигнатуры самой по себе не всегда достаточно.

[Повторить: std::function](../lectures/18-lambda.md#stdfunction){target="_blank"}

</details>

## this и копия объекта

Чем `[this]` отличается от `[*this]`?

::: {.quiz-options}
1. Второй запрещён в C++20.
2. Первый даёт доступ к исходному объекту через указатель, второй захватывает копию объекта.
3. Оба всегда создают копию объекта.
4. Первый продлевает жизнь объекта, второй нет.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**`[this]` сохраняет доступ к исходному объекту, `[*this]` копирует его.** Захват `this` не обеспечивает владение и не продлевает жизнь исходного объекта.

[Повторить: Capture](../lectures/18-lambda.md#capture){target="_blank"}

</details>
