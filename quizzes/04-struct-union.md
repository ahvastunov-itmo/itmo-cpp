## Структура данных

Для чего объединять координаты `x` и `y` в структуру точки?

::: {.quiz-options}
1. Чтобы запретить передачу точки в функцию.
2. Чтобы оба поля обязательно занимали один адрес.
3. Чтобы представить связанные данные одним типом.
4. Чтобы типы полей перестали проверяться.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Структура выражает связь данных.** Точку можно передавать и хранить как единое значение с отдельными полями.

## Именованные инициализаторы

Какое правило действует для designated initializers агрегата в C++20?

::: {.quiz-options}
1. Они доступны только для `union`.
2. Поля можно перечислять в любом порядке.
3. Именованные и позиционные инициализаторы всегда можно смешивать.
4. Имена полей должны идти в порядке объявления.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Соблюдается порядок объявления полей.** Некоторые поля можно пропустить, но смешивать именованные и позиционные инициализаторы нельзя.

## Доступ через указатель

`p` указывает на существующую структуру с полем `value`. Чему эквивалентно `p->value`?

::: {.quiz-options}
1. `(*p).value`.
2. `*p.value`.
3. `p[value]`.
4. `&p.value`.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**`(*p).value`.** Сначала получаем объект по указателю, затем обращаемся к его полю.

## Копирование структуры

У структуры только два поля типа `int` и нет пользовательских специальных функций. Что делает копирование?

::: {.quiz-options}
1. Всегда запрещено.
2. Копирует значения обоих полей.
3. Связывает все поля ссылками.
4. Копирует только первое поле.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Копируются оба поля.** Неявное копирование обрабатывает подобъекты; глубокое копирование внешних ресурсов этим автоматически не обеспечивается.

</details>

## Padding

Почему `sizeof` структуры может превышать сумму размеров её полей?

::: {.quiz-options}
1. Потому что каждое поле обязательно копируется дважды.
2. Потому что `sizeof` считает методы объекта.
3. Потому что имена полей всегда хранятся внутри объекта.
4. Из-за промежутков и хвостового дополнения для выравнивания.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Причина — padding для выравнивания.** Дополнение в конце позволяет соблюдать выравнивание и для следующих объектов в массиве.

## Уплотнение и скорость

Гарантирует ли `#pragma pack(1)` ускорение обработки структур?

::: {.quiz-options}
1. Нет: экономия памяти конкурирует с ценой невыровненного доступа.
2. Да, все поля становятся атомарными.
3. Да, меньший размер всегда означает меньшую задержку.
4. Нет: программа с ним всегда не компилируется.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Ускорение не гарантировано.** Уплотнение — расширение компилятора; эффект зависит от доступа к памяти, платформы и данных, поэтому его измеряют.

[Повторить: Меньше памяти — медленнее обработка?](../lectures/04-struct-union.md#меньше-памяти-медленнее-обработка){target="_blank"}

</details>

## Усиление выравнивания

Зачем в примере лекции разносить изменяемые разными потоками данные по кеш-линиям с помощью `alignas`?

::: {.quiz-options}
1. Чтобы гарантировать меньший размер структуры.
2. Чтобы уменьшить false sharing.
3. Чтобы заменить мьютекс при записи в один объект.
4. Чтобы скрыть поля от других потоков.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Чтобы уменьшить false sharing.** Разные данные меньше мешают друг другу в кеше; синхронизацию доступа к одному объекту выравнивание не заменяет.

[Повторить: alignas: зачем увеличивать выравнивание](../lectures/04-struct-union.md#alignas-зачем-увеличивать-выравнивание){target="_blank"}

</details>

## Общая память union

Что отличает поля `union` от обычных полей `struct`?

::: {.quiz-options}
1. Все всегда существуют как независимые объекты.
2. Размер всегда равен сумме размеров полей.
3. Альтернативы используют общую область памяти.
4. Каждое хранится в отдельном массиве.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Поля-альтернативы разделяют память.** Размер должен вмещать наиболее крупную альтернативу с учётом выравнивания.

</details>

## Активное поле

Почему нельзя в общем случае записать `double` в `union`, а затем прочитать его как поле `int`?

::: {.quiz-options}
1. Такое чтение всегда выполняет числовое преобразование.
2. `union` не допускает числовые типы.
3. Такое чтение всегда возвращает ноль.
4. Чтение неактивного поля в общем случае даёт неопределённое поведение.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**Чтение неактивного поля не является переносимым преобразованием.** Это анализ ошибки, а не пример для запуска; для работы с представлением используют подходящие средства вроде `std::bit_cast`.

[Повторить: Активное поле объединения](../lectures/04-struct-union.md#активное-поле-объединения){target="_blank"}

</details>

## Тег варианта

Какое преимущество даёт `std::variant` по сравнению с ручным tagged union?

::: {.quiz-options}
1. Сам хранит информацию об активной альтернативе и управляет её временем жизни.
2. Убирает необходимость учитывать тип альтернативы.
3. Всегда занимает один байт.
4. Он одновременно хранит все альтернативы как активные.
:::

<details class="quiz-explanation">
<summary>Ответ и объяснение</summary>

**`std::variant` управляет активной альтернативой.** Для обращения используют, например, `std::get_if` или `std::visit`; обработка остаётся типобезопасной.

[Повторить: std::variant](../lectures/04-struct-union.md#stdvariant){target="_blank"}

</details>
